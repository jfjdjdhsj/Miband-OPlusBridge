# Miband-OPlusBridge

<img src="icon.png" width="96" alt="Miband-OPlusBridge">

把小米运动健康能用 **SPP** 连上的手环接到 ColorOS **设备空间** 和 **OPPO 健康**。

在设备空间里管理这只手环，查看连接与电量，并把步数、心率、静息心率、步行平均心率、睡眠写入 OPPO 健康。健康同步可单独开关，间隔可用天、小时、分钟填写（5 分钟到 7 天），每次自动同步完成会在通知栏显示同步时间；也可以打开「打开 App 立即同步」，每次打开 App 时先同步一次。天气按设定的间隔自动刷新并推送，间隔可用天、小时、分钟填写（15 分钟到 7 天），自动同步同样可以开关，推送成功后通知栏显示同步时间。界面和日志统一使用中国时间（Asia/Shanghai），不跟随手机区域设置。手环没有上传睡眠文件时，睡眠改从小米运动健康本地数据库读取，仍然写进 OPPO 健康。睡眠除分期外还写呼吸率和心率范围：手环本身不上传呼吸包，这两项取自小米运动健康睡眠会话里的平均呼吸率与当夜最低 / 最高 / 平均心率，分别落到 OPPO 健康的呼吸率、睡眠指数和睡眠心率统计。静息心率取自手环每天的日报；步行平均心率按当天走路分钟的步数和心率推算，所以两者都按天各一条，和 OPPO 手表自己的口径一致。手机通知和来电转到手环，通知里显示应用自己的图标（手环查询图标时按它给的尺寸和像素格式回传），当前播放走 OPPO 健康自己的音乐控制。首页可打开「入睡后暂停音乐」：手环报入睡后暂停手机播放，醒来后保持暂停。通过睡眠记录报告入睡的手环，会在记录同步后暂停。手环查找手机会走 OPPO 健康自己的响铃，健康设备页也可以让这只手环响。健康首页若在导入完成前就打开，导入结束后会再读一次。日常在设备空间和 OPPO 健康里使用。小米手环 11 已实机验证。手环 8 / 8 Pro / 9 / 9 Pro / 10 / 10 Pro 及 NFC、活力版，官方重连是 SPP 或 GATT + WearAuthV2 即可导入接管。红米手表 5（含无 eSIM 版，型号 `miwear.watch.o65`）按 SPP V2 接管。SPP V2、SPP V1（8 Pro）和纯 BLE（fe95）在连接时按采集 profile 分支。纯 BLE 用已导入的密钥重连，系统蓝牙配对断开后照样能连；SPP 连接依赖系统蓝牙配对。

接管期间连接留在前台服务里重连。健康还在、服务被系统杀掉时，健康读卡片或转发通知会把服务拉起来。控制中心可以添加「手环」，下拉或点一下会拉起连接。后台限制拦住时用 root 启动。服务这边先把健康进程绑回来，绑定中断时改用 root 拉起健康。连接还在建立时，通知先留着，连上后续发；普通通知保留 60 秒，来电保留 15 秒。健康在后台拉起的是连接服务。通知保持一条折叠的「手环已连接」。OPPO 健康的追踪 SDK 如果在自己拿到应用上下文之前就初始化，会直接空指针崩掉，模块在它初始化前先拦住，等上下文就绪再放行，所以打开 OPPO 健康不会再闪退。

## 安装

1. 安装支持 libxposed API 102 的框架（Zygisk），例如 [Vector](https://github.com/JingMatrix/Vector)。1.6.8 之后的版本按 API 102 加载，框架要支持这个 API。
2. 安装本模块 APK，在 LSPosed 中启用，作用域勾选：
   - `com.heytap.mydevices`（设备空间）
   - `com.heytap.health`（OPPO 健康）
   - `com.mi.health`（导入绑定时需要）
   - `com.coloros.alarmclock`（时钟）
3. 在 KernelSU 里对本应用授权。拿到 root 后，本应用会在 ColorOS 里给自己和 OPPO 健康打开「自启动」和「关联启动」。这两项开着时，更新模块后 OPPO 健康会拉起桥接。更新后打开一次本应用，也能把桥接拉起来。
4. 打开「小米手环桥接」：检查 Root → 导入绑定（从本地数据库读密钥）→ 添加到健康。手环 8 及以后使用已确认的蓝牙参数，导入后直接添加即可。
5. 第一次安装，或从 1.6.8 及以前的版本升级时，强停「设备空间」和「OPPO 健康」后再打开。之后的更新会热重载。
换到本包名后重新导入。旧包名 `io.github.oplusband.bridge` 的数据留在原包里。

## 界面

首页从上到下：手环状态和一个主按钮 → 首次设置清单（三步，完成后隐藏）→ 待处理事项（附近设备、通知、OPPO 健康通知使用权）→ 功能 → 帮助 → 管理 → 高级设置。界面跟随系统深色模式。

## 历史步数汇总核对

同步后，桥接会核对近期历史日期的完整分钟记录、设备日总与健康合并日总。满足完整性和设备归属校验的差异，显示在「设备详情 → 日汇总核对」。分钟证据覆盖全天 1440 分钟，并与健康逐分钟的步数、热量、距离精确一致后，才提供校正入口。

核对当天实际步数后，点「核对并校正」确认指定日期。合并日总也可能包含真实手机计步；需要保留这部分数据时，选择「保留现状」。确认绑定当前账号、设备、日期和证据指纹，数据变化后重新核对。

校正在健康已有数据库服务中执行：事务内重取证据，只下调获准的偏大合并步数，其余运动指标保留，目标完成状态和同步标记由健康原生流程更新。提交后再次读回确认，再刷新核对记录。重新打开健康页面可查看汇总。

## 热重载

模块在 `META-INF/xposed/module.prop` 里声明 `autoHotReload=true`。宿主进程运行时安装新版 APK，框架会在宿主里换成新代码，宿主进程持续运行：旧代码先停掉自己的线程、广播接收器和内容观察者，新代码移除旧 hook 并重新装上。已经打开的页面要刷新一次才显示新代码画的内容。

- 只有 versionCode 变了才会触发。开发时用 `python3 tools/build.py :app:assembleDebug -PhotReloadVersionCode=<更大的数>`，再 `adb install -r`。之后要装回正常版本号，用 `adb install -r -d`。
- 被系统冻结的后台进程，下次启动时直接加载新版本。
- 从 1.6.8 及以前升级的那一次，按第 5 步强停后再打开。

## 协议测试

首页 → 高级设置 → 调试 → **协议测试**：

- 设备信息（名称、型号、固件、电量、连接；MAC 只显示末位）
- 测试通知 / 撤回
- 测试来电 / 结束来电（手表靠手机的 HFP 通道显示来电，所以会先建立一通自管理的测试来电，再补发来电通知包）
- 同步免打扰（同步开关 + 当前状态）
- 测试闹钟响铃 / 关闭 / 稍后响
- 测试查找手机 / 停止查找（OPPO 健康自己的响铃）
- 发送测试音乐
- 检查更新（GitHub Releases）

手环连上后即可测试。

首页「帮助」→ **发送调试日志**：生成本机连接日志，优先交给 QQ，也可选其他应用。日志写出阶段、型号、队列和帧类型。

## 发布

推送 `main` 即自动发版：GitHub Actions 跑单测、构建签名 APK、打 tag 并发布 Release，不用手动打 tag。

```
git push origin main
```

- 版本号由工作流运行号决定：第 N 次运行产出 `versionName 0.0.N` / `versionCode N`，tag 为 `v0.0.N`。
- Release 说明自动汇总上一个 `v0.0.*` tag 以来的提交标题；提交正文写进「修复与改动」。
- `workflow_dispatch` 手动触发走同一套流程。
- 本地构建不注入版本时固定为 `versionCode 1` / `versionName 0.0.1`。
